# Hisab v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship four things on the existing PWA without changing a single existing row or ledger rule:
- Google sign-in with safe linking of existing accounts
- the Forest & Brass redesign (Direction A, tabs Home · Activity · + · Loans · Wealth)
- foreign-currency pots and gold/silver in a per-person and household net worth
- SMS capture into drafts

**Architecture:**
- Next.js 16 App Router and Postgres (Drizzle), as today.
- Every schema change is additive: new tables or nullable columns in `00xx` generated migrations, plus idempotent `01xx` views and triggers and an extended `0109_rls.sql`.
- Pure rules live in `src/lib/*.ts` and are proved by `test:lib`. Database rules are proved by `test:invariants`. Screens are proved by a Playwright device sweep.

**Tech Stack:**
- Already in the app: Next 16, React 19, Auth.js v5 (Credentials + Google), postgres.js, Drizzle, Tailwind 4, shadcn/ui (Radix, vaul, sonner, cmdk).
- Added: shadcn registry Chart (Recharts), Calendar (react-day-picker), Carousel (Embla), Toggle Group; `@number-flow/react`; Material Symbols Rounded (subset woff2 via `next/font/local`); Inter via `next/font/google`; Playwright (preinstalled) for the sweep.

**Spec:** `docs/superpowers/specs/2026-11-06-hisab-v3-design.md`. Read it first; section numbers below (§) refer to it.

## Global Constraints

- **Additive only:**
  - No existing column changes type, meaning or default.
  - No existing row is updated by a migration.
  - Before each production migration, take a Neon branch as the rollback point.
- **Money:** integer minor units, as everywhere. Rates are `numeric(24,10)`, never JS floats in SQL arithmetic. Valuation rounds once, half-even, in SQL.
- **Currency formatting:** only through `src/lib/money.ts` (`format`, `digitsOf`, `useMoney()`). Nothing else multiplies or divides by 100.
- **No hand-written CSS:**
  - New UI uses Tailwind utilities and shadcn components.
  - `ql.css` token *values* may change. No new stylesheet and no new class rules.
  - `globals.css` may only shrink.
- **Icons:** Material Symbols Rounded only, through `<Icon>`. Tabler is removed by the end of Task 8.
- **Palette (light):**
  - Ground `#F4F1EA`, card `#FFFFFF`, ink `#1B1E1B`, muted `#5D605A`, track `#E8E3D8`.
  - Primary `#1E4D3A` with white text; primary-soft `#E2ECE6` with ink `#163A2C`.
  - Brass Add `#C9A35B` with ink `#1B1E1B`; brass mark on paper `#8C6A2E`.
  - Attention `#F6ECD8` with ink `#7A5A1F`; money-in `#15803D`; danger `#B91C1C`.
- **Palette (dark):**
  - Ground `#0F1512`, card `#17201B`, ink `#E7ECE8`, muted `#A3ADA6`.
  - Primary `#8FC9A9` with ink `#0D1A13`; brass `#D9B977` with ink `#1B1E1B`.
  - Attention `#3A2E14` with ink `#F0D9A6`; money-in `#86D19F`; danger `#F2867A`.
- **Interaction:** tap targets ≥ 44 px (Android icon buttons 48 px). Every status shows an icon and a word. Fields are ≥ 16 px.
- **Server Actions** take `(prevState, formData)`. They resolve household and role on the server, run inside `withHousehold`, and call `rethrowControlFlow(e)` first in every catch.
- **Copy:** plain voice, as in CLAUDE.md "The voice". Name changes: "Money" → **"Wealth"**. "Pots" are foreign-currency holdings. "Gold & silver" are metal holdings.
- **Service worker:** bump `VERSION` in `public/sw.js` whenever `/offline` or anything it renders changes.
- **Local verification DB:**
  - Postgres 16 with TLS on `localhost:5433`, database `saree`.
  - Run every script as `DATABASE_URL="postgresql://postgres@localhost:5433/saree?sslmode=require" …`.
  - `web/.env.local` holds the same URL plus `AUTH_SECRET` and `AUTH_TRUST_HOST=true` (gitignored).
- **Commits:** end every commit message with the session's two attribution lines. Push to `claude/gracious-galileo-izewvb`.

## Review Focus

1. **Currencies with 3 or 0 minor digits.** A KWD pot (fils) or a JPY pot valued into INR must land on the right paisa. *Test: Task 13, invariants "KWD/JPY valuation".*
2. **A rate never fetched, or the provider down the first time.**
   - The holding shows its native amount and "not valued yet", is left out of the total, and the screen says so.
   - Never zero, never a crash.
   - *Test: Task 15 `netWorth` "unvalued"; Task 17 sweep fixture with no quotes.*
3. **The same SMS forwarded twice, and OTP messages.** One draft only; an OTP is never stored. *Test: Task 20 `isOtp`; Task 21 duplicate POST → one row.*
4. **Email case differs between Google and the stored address** (`Ammar@Gmail.com` vs `ammar@gmail.com`). It must be recognised as the same person: lowercase compare, no other normalisation. *Test: Task 2 decision table.*
5. **A holding or account owned by someone later removed from the household.**
   - It must not vanish from the household total.
   - It counts as **Joint** in the owner filters, and no "member" chip is shown for a non-member.
   - *Test: Task 15 `netWorth` "former member".*

### Task 2: The sign-in decision, as a pure function

**Files:**
- Create: `src/lib/google-signin.ts`, `src/lib/google-signin.test.mjs`

**Interfaces:**
- Produces:

```ts
export type GoogleClaims = { sub: string; email: string; emailVerified: boolean };
export type SignInFacts = {
  identityUserId: string | null;      // user already holding (google, sub)
  sessionUserId: string | null;       // signed in right now
  linkIntentUserId: string | null;    // from a valid link-intent cookie
  sessionUserHasGoogle: boolean;
  emailOwnerId: string | null;        // app_user with lower(email) = lower(claims.email)
  invite: { email: string } | null;   // an open invite being accepted
};
export type Decision =
  | { kind: 'signin'; userId: string }
  | { kind: 'link'; userId: string }
  | { kind: 'create' }
  | { kind: 'join-existing'; userId: string }   // invite accepted by an existing linked user
  | { kind: 'refuse'; code: 'exists-link-first' | 'already-linked' | 'invite-mismatch' | 'unverified' };
export function decideGoogleSignIn(c: GoogleClaims, f: SignInFacts): Decision;
```

- [ ] **Step 1: Write the table test.** One `assert.deepEqual` per row:

| Case | Facts | Expected |
|---|---|---|
| Known sub | `identityUserId:'u1'` | `{kind:'signin',userId:'u1'}` |
| Unverified | `emailVerified:false` | `refuse unverified`, even if `identityUserId` is set |
| Link | `linkIntentUserId:'u2'`, `sessionUserId:'u2'`, no google | `{kind:'link',userId:'u2'}` |
| Link, already linked | the same, but `sessionUserHasGoogle:true` | `refuse already-linked` |
| Link to a sub owned by someone else | `identityUserId:'u9'`, `linkIntentUserId:'u2'` | `refuse already-linked` |
| Link intent for someone other than the session | `linkIntentUserId:'u2'`, `sessionUserId:'u3'` | not linked; falls through to the email rule |
| Email exists, case differs | claims `Ammar@Gmail.com`, `emailOwnerId:'u4'` | `refuse exists-link-first` (Review Focus 4: the lookup is done lower-cased by the caller; the test fixes that `decide` never creates when `emailOwnerId` is set) |
| New person | nothing set | `{kind:'create'}` |
| Invite, match | invite `X@y.com`, claims `x@Y.com`, no owner | `create` |
| Invite, match, already linked | invite matches and `identityUserId:'u5'` | `{kind:'join-existing',userId:'u5'}` |
| Invite, mismatch | invite `a@x.com`, claims `b@x.com` | `refuse invite-mismatch` |
